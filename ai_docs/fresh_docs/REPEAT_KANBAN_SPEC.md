# Канбан повторных продаж — спецификация (решения владельца 20.10.2026)

Раздел в «Ещё»: `/repeat-kanban`. Карточка = **заказчик** (clientKey из «Моих
заказчиков»), не сделка. Видимость — как в «Моих заказчиках»: менеджер видит своих,
РОП — свой отдел (`fetchTeamRoster`), действия РОПа — только над менеджерами своей зоны.
Отдельного права «РОП повторных продаж» нет — хватает обычной роли РОПа.

## Рабочий цикл (слова владельца)

РОП смотрит пул слева → находит перспективного → кнопкой создаёт повторную сделку в
Битриксе и ставит менеджеру задачу в Монолитике → проверяет: задача прочитана, отмечена
выполненной, был ли звонок. Не выполнено — разговор с менеджером. Выполнено — либо по
сделке видно движение (стадию сменили), либо сделку закрыли в отказ и РОП вручную
подтверждает брак (смотрит звонки: правда ничего не нужно / недозвон / послали).

## Колонки

**Пул (нет открытой повторной сделки, заказчик не в браке):**
1. 1 отгрузка
2. 2–4 отгрузки
3. 5+ отгрузок («Золотые рыбки»)

Число отгрузок = `purchasesDelivered` (покупки по правилу `lib/metrics/repeatRule.ts`).
Сортировка внутри колонки: тип клиента → шанс × сумма (`expectedValue`).
Порядок типов (`sa.client_module_profiles.client_type`): Прораб → Строительная
организация → Строит себе (начало) → Строит себе (середина/окончание) → Организация под
свои нужды → не указан. Сверху — чипы-фильтры по типу.

**Окно 22 дня — контакты (сделка в стадии «Сделка» C2:NEW / C3:NEW):**
4. Контакт 0/3 · 5. Контакт 1/3 · 6. Контакт 2/3 · 7. Контакт 3/3 (можно закрывать)

Окно (решение 20.10): свежий заказчик после первой отгрузки попадает в колонки контактов
сам, на 22 дня от отгрузки, без РОПа; заказчик, взятый РОПом из пула, — на 22 дня от
постановки задачи. Контакт засчитывается по НЕДЕЛЯМ окна (3 звонка в один день ≠ правило):
неделя закрыта, если в ней был звонок > 20 с (`va.calls`) или ручная отметка контакта
(`customer_contacts`). Недозвоны показываются на карточке отдельно.

**Рабочие стадии (стадии повторных воронок B2C/B2B, сведены по смыслу):**
8. Созвонился, уточнил материалы — C2:3, C3:3
9. Запрос снабженцу — C2:PREPARATION, C3:PREPARATION
10. Заполнил материалы / КП — C2:PREPAYMENT_INVOICE, C3:PREPAYMENT_INVOICE
11. Цена дешевле — C2:4, C3:4
12. Бронь — C2:EXECUTING, C2:5, C3:EXECUTING, C3:FINAL_INVOICE
13. Продано — C2:FINAL_INVOICE, C3:1
После отгрузки (C2:WON / C3:WON) заказчик возвращается в пул ступенью выше.
ВНИМАНИЕ: id стадий обманчивы (C2:1 — отказ, C3:1 — продано; C3:EXECUTING — счёт/бронь).
Сверено по `crm.dealcategory.stage.list` 20.10.

**Разбор:**
14. Отказ на проверке — сделка закрыта в отказ (C2:LOSE, C2:APOLOGY, C2:1, C2:2, C3:LOSE,
    C3:APOLOGY, C3:2), решения РОПа ещё нет. На карточке: звонки с длительностью,
    контакты по неделям, причина. Отказ до 3/3 — красная плашка; принять такой отказ
    можно только с явным комментарием.
    Кнопки: **Брак** (с причиной) · **Недозвон** (не брак, назад в пул с пометкой) ·
    **Вернуть менеджеру**.
15. Брак — подтверждённые РОПом. «Ничего не нужно» → тоже брак (решение 20.10).

## Задачи (в Монолитике, не в Битриксе)

Таблица в БД system. Поля: заказчик, сделка, менеджер, текст, срок, кто поставил;
`read_at` (менеджер открыл), `done_at` (отметил выполненной). Уведомление менеджеру —
ботом «Аналитик» со ссылкой. На карточке:
`📋 поставлена · 👁 прочитана · ✅ выполнена · 📞 звонок после постановки`;
«выполнена, но звонка нет» и просрочка — красным.

## Кнопка «Сделка + задача»

Порядок (правило владельца 20.10): открытая повторная сделка есть — задача к ней;
последняя повторная в отказе — **откатываем её** в «Сделка» (C2/C3:NEW) на исполнителя
(`crm.deal.update`), кнопка на карточке «Вернуть сделку + задача»; стадию «НЕ ТРОГАТЬ —
ЗАПРЕЩЕНО» (C2:2) не трогаем — ошибка; иначе — новая сделка, как ниже.

Повторяет создание сделки ИЗ КОНТАКТА в Битриксе (так делают менеджеры; разбор 100
последних повторных сделок 20.10): `crm.deal.add` с CATEGORY_ID 2 (контакт) / 3
(компания), STAGE_ID `C2:NEW`/`C3:NEW`, CONTACT_ID, COMPANY_ID, SOURCE_ID и
SOURCE_DESCRIPTION из контакта, ASSIGNED_BY_ID — выбранный РОПом менеджер (по умолчанию
ответственный контакта), OPENED=Y, TYPE_ID=SALE, CURRENCY_ID=RUB, TITLE пустой (Битрикс
сам даёт «Сделка #ID»). Копию прошлой сделки НЕ делаем: копия тащит старые отметки
времени («Дата и время заказ в работе» и т.п.).

## Этапы постройки
1. Движок + доска на чтение (все колонки, контакты по неделям, тип клиента).
2. Задачи: таблица, постановка, бот, прочитано/выполнено, индикаторы на карточке.
3. Кнопка «Сделка + задача» (`crm.deal.add`).
4. Разбор отказов (брак / недозвон / вернуть), правило 3/3.
