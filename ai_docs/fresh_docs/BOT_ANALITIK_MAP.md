# Бот «Аналитик» — карта интеграции (для сверки владельцем)

Составлено 05.08.2026 сплошным чтением кода (запрос владельца: «освежи всё, что
заложено во взаимодействие с „Аналитиком“ — хочу свериться и может что-то поменяю»).
Все пункты с адресами `файл:строка` на момент составления.

## 0. Главное в двух строках

Ботов **два**: «Аналитик» (BOT_ID 20761) и «Контроль звонков» (15010) — разные креды,
разные каналы. И **три независимых глушилки**, действующих каскадом:

| # | Глушилка | Где | Состояние |
|---|---|---|---|
| 1 | `BOT_SEND_ENABLED` (env) | `lib/bitrix/notify.ts:77` | НЕ выставлен → наружу уходят только сообщения с `channel:'report'` |
| 2 | `bot_settings.dry_run_managers` | `features/badges/engine/notifications.ts:62` | дефолт `true` → вся менеджерская аудитория в лог, не в чат |
| 3 | `NODE_ENV !== 'production'` | `instrumentation.ts:21` | джобы не стартуют локально |

**Фактическое состояние: из «Аналитика» реально уходят ТОЛЬКО два ежедневных отчёта.**
Всё остальное собирается, логируется и молчит. Это соответствует режиму «до релиза».

## 1. Что бот шлёт

### Реально уходит сейчас
- **Отчёт «МОСКВА»** + отдельным сообщением сверка «Битрикс ↔ БД» → владельцу
  (`DAILY_REPORT_BITRIX_USER_ID`), окно 18:00–19:59 МСК, BB-код, без кнопок.
- **Отчёт «КОВАЛЕНКО»** (5 команд ОС) + сверка → `1923` (**хардкод** в
  `dailyOsTeamsReport.ts:28`, env только переопределяет).

### Молчит (готово, но заглушено)
- **Дайджест менеджеру** — дневной (Пн-Пт, час из настроек, дефолт 8 МСК) и недельный
  (Пн). «Гамбургер»: похвала → укор → похвала + подсказка «кому позвонить», ссылка в ЛК,
  кнопки «⚠️ Ошибка» / «👍 Полезно», метка `ID:xxx`.
- **Дайджест РОПу** по отделу — те же часы, свои подсказки (падение конверсии,
  непрозвоненные брони, остывающий заказчик).
- **Циклы обратной связи** по подсказкам (менеджерам и РОПам): «интерес подтвердился»,
  «момент всё ещё хороший» — не чаще раза в 3 дня, максимум N напоминаний.
- **Геймификация** (~17 типов): награда, новый уровень, «скоро сгорит N MLT», гача,
  квесты и контракты, покупка, перевод, подарок, конвертация, ручное поощрение/штраф,
  результат заявки на активацию, результат выплаты, события ПИНа.
- **Утилитарное**: вопрос по сделке РОП→менеджер и весь диалог деал-чатов,
  **инвайт новому пользователю со ссылкой на пароль**, скрипт виджета, «спасибо» за фидбек.

## 2. Что бот принимает

Единственная точка входа — `app/api/bitrix/events/route.ts` (всегда отвечает 200).

- **Текст в личку** → корреляция ответа со сделкой по 4 ступеням: `REPLY_ID` → номер
  сделки в тексте → единственный открытый тред → иначе кнопки выбора.
- **Три кнопки, других в коде нет**: `bind_deal` (к какой сделке ответ),
  `advice_error`, `advice_useful`.
- Свободный текст вне контекста тредов **игнорируется**; NL-разбор помечен как Phase 2
  и не реализован.

## 3. Подтверждения через бота — ИХ НЕТ

Проверено исчерпывающе. Ни одной кнопки «одобрить/отклонить» в чате не существует.
Все подтверждения (активация отгула, выплата в ЗП, поощрения) делаются **в вебе**;
бот только уведомляет заявителя о результате — и сейчас даже это молчит.
Руководителю о НОВОЙ заявке бот не пишет вообще.

→ Отсюда задача владельца 05.08: раздел «Заявки» в вебе (сделан) + быстрое
подтверждение кнопкой в боте (не сделано, требует регистрации imbot-команд).

## 4. Настройки, влияющие на отправку

| Что | Где лежит | Где меняется |
|---|---|---|
| Глобальная тишина | env `BOT_SEND_ENABLED` | **только start.sh + рестарт, экрана нет** |
| Dry-run менеджерам | `bot_settings.dry_run_managers` | **только SQL, ни экрана, ни API** |
| Дайджест вкл/часы/лимиты | `digest_settings` | Настройки → Геймификация → Дайджест |
| Личная подписка менеджера | `manager_bot_prefs` | ЛК → Настройки → Бот «Аналитик» |
| Личная подписка РОПа | `rop_bot_prefs` | там же (только у кого есть подчинённые) |
| Просмотр чужих подписок | — | Настройки → Подписки (только чтение) |

Финансовые пуши (переводы, выплаты, сгорание) **не отключаются подпиской** — решение
владельца; гасятся только dry-run’ом или глобальной тишиной.

## 5. Наблюдаемость

`bot_outbound_log` — каждое сообщение менеджерской аудитории: текст, триггер, dry-run,
отправлено/подавлено, `decision_trace`. Экран: Настройки → Геймификация → **Исходящие**
(поиск по ID из самого сообщения). Клики по «Ошибка/Полезно» — `bot_feedback` + экран
«Обратная связь».

**НЕ логируются**: оба ежедневных отчёта, деал-чаты, инвайты, виджет-скрипт,
«Контроль звонков».

## 6. Дыры, найденные при составлении карты (нужны решения владельца)

1. **Инвайты молча не доходят.** Отправка глушится тишиной, возвращает `0` без ошибки,
   API отдаёт `201 OK`. Пользователь создан, ссылку не получил, админ уверен, что ушло.
   Ссылка нигде в интерфейсе не показывается — достаётся только из БД. **Худшая из дыр.**
2. **Деал-чаты ломаются необратимо.** Исходящее сообщение глушится → `bitrix_message_id`
   пишется NULL → корреляция по `REPLY_ID` для этих тредов невозможна НАВСЕГДА, даже
   после снятия тишины. UI при этом показывает тред как отправленный.
3. **Подсказки выгорают вхолостую.** Запись в `advice_log` делается ДО того, как ясно,
   уйдёт ли сообщение; потом цикл шлёт напоминания по советам, которых человек не видел,
   и ставит 30-дневный cooldown на пару (менеджер, клиент).
4. **Два рубильника надо снимать одновременно** — снятие только `dry_run_managers`
   ничего не даст, нужен ещё `BOT_SEND_ENABLED=1`.
5. **Дайджест уходит НЕ менеджерам, а всему активному ростеру** — логистам, HR,
   служебным аккаунтам. Им каждое утро «Сегодня без ярких цифр».
6. **Дайджесты менеджеров и РОПов в один час** — ~400 получателей двумя
   последовательными циклами должны уложиться в часовое окно.
7. **Кнопка «Ошибка» — тупик**: админ обязан написать комментарий при разборе, но
   менеджеру он не уходит ни ботом, ни в уведомления.
8. **imbot-команды не воспроизводимы из репозитория** — зарегистрированы вручную,
   скрипт обновления событий их не трогает. При смене домена сообщения будут ходить,
   а **все кнопки молча умрут** (инцидент 20.07 уже был).
9. `bot_outbound_log` растёт без TTL и чистки (полный текст + jsonb на каждого
   ежедневно).
10. **Пропуск отчёта не сигнализируется** — если все попытки в окне упали, только
    `console.error` (прецедент 30.07).
11. Получатель отчёта «КОВАЛЕНКО» и состав команд ОС — константы в коде.
12. `deliverTo` в тест-роутах позволяет доставить чужой персональный дайджест третьему
    лицу, причём в лог запишется получатель, а не тот, про кого дайджест.
13. Мёртвый планировщик `scheduleEmployeeRenameCheck` (no-op с задачи 2820) крутится
    впустую.
14. Фильтр «Исходящих» не знает типов РОП-дайджестов — их через фильтр не найти.
