# «Телевизоры» — ТВ-дашборды отделов продаж

ТЗ владельца 07.09.2026. Телевизоры в кабинетах отделов показывают продажи «сегодня»
по менеджерам отдела, а админка в Монолитике («Ещё → Телевизоры», право `section.tv`)
управляет тем, что на них крутится, и шлёт сообщения.

## Как подключить телевизор (памятка)

1. На телевизоре в браузере открыть `monolitika.mlt-it.com/tv` и сохранить как
   домашнюю страницу / закладку (вводится один раз).
2. На экране появится код из 4 символов (без 0/O/1/I, живёт 20 минут, потом сменится).
3. В Монолитике: «Ещё → Телевизоры» → у нужного экрана «Привязать телевизор» → ввести код
   и подпись «где висит». Через 5 секунд телевизор сам покажет дашборд.
4. В настройках телевизора отключить: таймер сна, экономию энергии, скринсейвер.
   Страница этого сделать не может — только сам телевизор.
5. Перепривязать к другому экрану — «Отвязать» в карточке экрана: телевизор снова
   покажет код. Никакого ввода URL повторно не нужно.

Вторая дорога — прямая ссылка `/tv/s/<токен>` (кнопки «Ссылка»/«Открыть» в карточке
экрана). Она же — превью в админке (`?preview=1`, без звука событий). «Новая ссылка»
перевыпускает токен; привязанные по коду телевизоры это не затрагивает.

## Что показывает экран

- Заголовок отдела, крупно план дня / факт / выполнение (зелёный при ≥100 %) / брони;
  плитки менеджеров по убыванию суммы продаж (лидер подсвечен), в плитке: сумма и штуки
  продаж, % личного плана, прогрессбар, план и брони, внизу крупно «ПРОДАЖЕБРОНЕЙ: 4 / 5»
  — продажи + брони по количеству против дневной цели экрана (по умолчанию 5), зелёным
  при достижении (правка владельца 07.09: у менеджера бонус за ≥5 в день).
  Формат сумм: «12,5 млн ₽», «754 тыс ₽».
- Страницы отдела: первая — топ-6 по продажам (висит `rotateSec`, 15 с), дальше «хвост»
  по 20 плиток (висит `settings.rotateTailSec`, 10 с); отдел ≤6 человек — одна страница.
- Несколько отделов: карусель страниц (точки внизу, стрелки ←/→ с пульта) или «одна
  сетка» (все менеджеры вместе, заголовок «А + Б»).
- Тема тёмная/светлая. «Сегодня» — календарный день МСК, сброс в полночь автоматически.
- Бегущая строка — **своя у каждого отдела** (`settings.deptTickers`, правка владельца
  07.09: ЖБИ читает остаток склада, ОС МСК — «скандик по 899 с Петровича»); если у отдела
  строки нет — общая строка экрана; `ticker_enabled` — мастер-выключатель своих строк.
  В карточке экрана быстрая правка с выбором «Общая / отдел». Плюс рассылки («Рассылки»:
  бегущая строка / баннер сверху / на весь экран; адресат — все экраны или выбранные;
  длительность). Бегущая строка рассылки **перекрывает** строку экрана/отдела, пока
  активна (правка 07.09: «она важней»). Баннер — по центру. Полноэкранное — без подписи,
  можно с картинкой на фон (`tv_messages.image_id` → `tv_media`, миграция 202; админка
  ужимает картинку до 1920px JPEG, отдача `/api/tv/media/<id>` с immutable-кэшем,
  сироты старше суток чистятся при следующей загрузке).
- События («мувики»): новая продажа (порог суммы), отдел выполнил план дня. Оформление
  конфетти/вспышка/тихий тост, длительность, звук (best-effort: ТВ-браузер может не дать
  автоплей). Включаются на экране.
- Обновление раз в 15 с; при потере связи — плашка «нет связи · данные на HH:MM»,
  цифры остаются. Перезагрузка страницы при смене BUILD_ID (деплой) и ночью (03–05 МСК,
  если страница живёт дольше 20 ч) — от утечек памяти старых телевизоров.

## Кто попадает на плитки (правило владельца 07.09)

Состав отдела — `org_resolved_hierarchy` с `is_active = true`; в нём ~76 из 431 строк —
свободные слоты Битрикса с именем-логином (`manager2014`, `Manager 307`, `User 4398`).
Правило: **нормальное ФИО — показываем; имя-заглушка — только если были продажи или
брони за последние 5 рабочих дней** (Пн–Пт без праздников). Так manager2204 — человек на
слоте без ФИО, который продаёт — остаётся, а лечится заполнением ФИО в Битриксе. Итоги
шапки — по видимым плиткам.

## Данные

`features/tv/engine/feed.ts`: факты — каталог метрик через `buildCollectedSQL`
(продажи перв.+повт. по `sold_at`, брони по `reserved_at`) с группировкой по
`current_manager_id`; план дня — `computePeriodPlanByLogin(today, today, today)`; состав
отдела — `resolveManagersForDepartments` (uuid отделов, вложенные команды включены);
аватары — bulk из `manager_avatars`, недостающие догружаются в фоне. Кэш фида в Redis
20 с на экран. Список продаж дня — для событий (клиент сравнивает id между опросами).

## Совместимость с телевизорами (почему страница без React)

Движки встроенных браузеров: Samsung Tizen 2017–2019 — Chromium 47–63; LG webOS 3.x/4.x
(2016–2019) — Chromium 38/53; новее — 68–120. Поэтому `features/tv/engine/page.ts`:
готовый HTML из route handler-а, CSS без custom properties (тема классом, размеры плиток в
em от font-size, который ставит JS), flexbox с `-webkit-`, сетка плиток —
`position:absolute` в px, JS строго ES5 (XHR, без fetch/Promise/Intl; форматирование сумм
своё), шрифт — системный стек. Проверка синтаксиса: `npx acorn --ecma5` на извлечённом
скрипте.

## Права и скоуп

`section.tv` — вход в раздел. Руководство (`hasFullManagerAccess`: супер-админ,
Администратор, Директор) — все экраны, рассылка «на все». Остальные с правом — только
экраны, все отделы которых входят в подконтрольные (`managedDepartmentIds` + потомки),
рассылки адресно на них (`features/tv/engine/access.ts`).

## Защита публичных адресов

`/tv`, `/tv/s/*`, `/api/tv/feed`, `/api/tv/device` — без сессии (proxy.ts PUBLIC по
сегменту пути). `X-Robots-Tag: noindex` + `<meta robots>` + `robots.txt` (Disallow /tv,
/api/). Лимиты на IP (features/tv/engine/rateLimit.ts): регистрация устройства 5/10 мин,
фид 30/мин, попытки привязки 20/10 мин на пользователя. Токен экрана 16 символов
[a-z0-9] (80 бит), токен устройства 128 бит. Непривязанные устройства старше недели
чистит `purgeStaleDevices` (дёргать из джобы — см. BACKLOG).
