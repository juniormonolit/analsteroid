### Дерево скиллов + ротация порогов наград — схема закрыта, ждёт очереди
`PROGRESSION_IDEAS.md` §5-бис и §5-тер. Владелец утвердил: пороги 2/5/9/14/20
открывают новые награды, множители символические (+5 % XP и +1 % MLT за порог),
низкоуровневые награды после прокачки повышают порог. Плодить надо не 50 наград,
а 10 веток × 5 тиров — `badge_definitions.tiered` и `badge_prices` это уже умеют.
Железное правило при постройке: **прокачка не должна снижать доход**, иначе
выгодно сидеть на низком уровне и фармить лёгкое.

### Частота наград у медианного менеджера
Цель владельца — ништяк раз в 2–3 дня, сейчас раз в 4. Лечится не ценой, а
**количеством поводов**: новые награды и ежедневные квесты (владелец их и так
планирует). Держать в голове при добавлении любой механики.

## 4. Известные ограничения, не требующие действий прямо сейчас

- **Цены наград применяются в момент начисления**, задним числом ничего не
  пересчитывается. Любой будущий ребаланс трогает только новые начисления.
- **TTL баллов = 12 мес** — регулятором расходов не является: симуляция года
  показала сгорание ≈ 0 при любом TTL, если люди тратят. Бьёт только по копящим.
- **Себестоимость товаров** (`shop_items.cost_rub`) заполнена не у всех позиций;
  где пусто, дашборд экономики оценивает по цене продажи × курс — завышает,
  о чём в UI есть оговорка.
