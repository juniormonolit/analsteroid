# Увольнятор: мастер черновика — UX-спецификация (v3, 24.11)

Источник: правка владельца 24.11 («по вкладкам, слева направо, чтобы всё чётенько и понятно»), спроектировано
Fable по контракту `features/dismissal/types.ts` и текущему `features/dismissal/ui/*`. Реализация — по этому документу.

## 0. Ограничения контракта, влияющие на UX
- Одно правило на всю повторку (`rules.deal_repeat`) — общее для шагов 1 и 2. Топ-клиент без `override.target` уходит по правилу шага 2; если там «Закрыть» — он закроется. Мастер обязан это показывать и блокировать запуск.
- Одно правило на всю первичку (`rules.deal_primary`, по кругу). Шаги 3/4 делятся по статичному `info.qualified`, не по текущему действию: спасённая строка остаётся на шаге 4.
- Одна причина закрытия (`repeatBrakReason`) на все закрываемые сделки повторки.
- Строки шага 4 без `brakAvailable` (воронки 4, 7) по умолчанию передаются — им нужен получатель.
- `planTotals` доработать: сейчас `repeat.skip` смешивает brak и skip — нужны `repeat.brak`, `repeat.skip` и разрез top/rest.

## 1. Каркас
**Контейнер** (`DismissalRunPage`): для черновика `max-w-[1100px]` → `max-w-[1680px]`, `px-3 sm:px-6`. Page-root остаётся `h-full overflow-y-auto overflow-x-hidden`.

**Шапка** (одна строка): `Увольнение: Имя` + бейдж; справа мелко `Собрано 24.11 14:02 · Пересобрать · Удалить черновик` (текстовые кнопки `min-h-11`). Поле комментария → шаг 6. WarnBox «ещё активен» / «старый черновик» — под шапкой.

**Степпер ≥lg**: `TabStrip` из tasker (`features/tasker/ui/shared/TabStrip.tsx`; role="tablist", родитель `min-w-0`), 6 вкладок `flex-1 min-w-[168px] min-h-14 px-3 rounded-lg`, `data-tab-key`. В вкладке: кружок `h-6 w-6 rounded-full text-xs` (номер/иконка состояния), название `text-sm font-medium truncate`, счётчик `text-xs tabular-nums text-[var(--color-text-muted)]`.

| Состояние | Кружок | Счётчик |
|---|---|---|
| не начат | `bg-[var(--color-bg-hover)]`, номер | `20 заказчиков` |
| есть незаполненное | `bg-[var(--color-warning)]/15 text-[var(--color-warning)]`, `AlertTriangle` 12 | `осталось 6` |
| готово | `bg-[var(--color-positive)]/15`, `Check` | `20 из 20` |
| пусто | номер, вкладка `opacity-60` | `нет` |

Активная — `bg-[var(--color-accent-soft)] text-[var(--color-accent)]`, нижняя черта 2px. «Не начат» → «готово» после первого захода при отсутствии блокеров (посещённые шаги — `sessionStorage`).

**Степпер <lg**: кнопка `min-h-11 w-full` «Шаг 2 из 6 · Остальная повторка ▾» + полоска из 6 сегментов `h-1 rounded-full` в цветах состояний; по тапу — `Popover` со списком шагов. Ленты нет — правило 12 не задействовано.

**Переходы свободные**, блокируется только запуск. `?step=top|rest|primary|brak|tasks|final` через `useUrlState` (mode `push`); по умолчанию — первый шаг со строками; `existing=1` сохранить.

**Нижняя панель** (sticky, glass-стили текущей): слева статус сохранения («Сохранено» / «Сохраняю…» / красное «Не сохранилось · Повторить»); справа `btnSecondary` «Назад» и `btnPrimary` «Далее: Остальная повторка →». На пустом шаге — «Пропустить →». Шаг 5 — «К итогу →». Шаг 6 — без «Далее». Итоговую строку «Передаём 49…» и красные чипы убрать.

**Раскладка шагов 1–4**: `grid gap-4 lg:grid-cols-[minmax(0,1fr)_360px] 2xl:grid-cols-[minmax(0,1fr)_420px]`. Слева — список (`card`), справа — панель «Кому сколько» (`lg:sticky lg:top-3 self-start max-h-[calc(100dvh-140px)] overflow-y-auto`). Над сеткой — заголовок шага `text-base font-semibold` + подзаголовок `text-sm muted max-w-[720px]`.

## 2. Шаг 1 — «Сладкая повторка»
Подзаголовок: «Лучшие заказчики по LTV и отгрузкам. Каждому выберите получателя вручную.»
Тулбар: `Топ [20]` (инпут `w-16`, логика `applyTop`) · поиск · фильтр-чипы «Все / Без получателя».
Строка-заказчик — CSS-grid (не `<table>`): `grid-cols-[28px_36px_minmax(0,1fr)_120px_72px_64px_240px]`, `min-h-14`, hover `bg-[var(--color-table-row-hover)]`: чекбокс · ранг `#3` muted · название `text-sm font-medium truncate` + под ним `text-xs muted` сделки ссылками «Стадия · 240 000 ₽» (>2 — «+3 сделки», раскрытие) · LTV `tabular-nums text-right` · отгрузок · сделок · получатель `SearchSelect` `w-full` placeholder «Кому?». Шапка колонок `text-[11px] uppercase muted`, липкая.
Без ручного получателя: ячейка `border-[var(--color-warning)]`, под ней `text-xs` «по правилу шага 2 → Иванов»; если правило шага 2 — «Закрыть»: красным «закроется — выберите получателя» (блокер).
Панель справа: «Кто получает» — `SearchMultiSelect` кандидатов (локальный state; старт = получатели из overrides ∪ targets правила) → плитки кандидатов (§8); клик по плитке при выделении = назначить выделенным. Внизу «Распределено 14 из 20 · LTV 12,4 млн из 18,0 млн», «Сбросить выбор».
Готово: у всех топ-клиентов есть ручной получатель.

## 3. Шаг 2 — «Остальная повторка»
Подзаголовок: «Остальных раздаём поровну — людям или отделу — либо закрываем. Можно частично.»
Панель сверху: `Segment` **«Людям» / «По отделу» / «Закрыть»**. Людям — `SearchMultiSelect`; По отделу — `SearchSelect` отделов (логика `RecipientRule`), подпись «Змейкой по рангу — LTV делится ровно. ~12 заказчиков каждому». Закрыть — `rule.action='brak'` + `SearchSelect` «Причина» (`REPEAT_BRAK_REASONS`) + WarnBox «Сделки уйдут в отказ с этой причиной. Заказчик остаётся в базе». Ниже — плитки «Кому сколько» + строка «Закрываем: 31 сделка».
Список — та же строка, колонка 7 — исход текстом: «→ Петров» / «закрыть» / «не трогать»; ручной — точка `bg-[var(--color-accent)]` + «↺».
Частично: выделить → BulkBar «Закрыть» / «Передать…» / «Вернуть к правилу». Быстрые: «Выделить: с LTV 0 · без отгрузок · все». Постранично по 50, «Показать ещё».

## 4. Шаг 3 — «Сладкая первичка»
Подзаголовок: «Бронь и дальше или чек от 100 000 ₽. Раздаём людям или отделу, по кругу.»
Панель: `Segment` Людям / По отделу + селект + плитки (сделок, сумма).
Строка-сделка: `grid-cols-[28px_minmax(0,1fr)_160px_120px_150px_220px]`: чекбокс · название (ссылка) · стадия · сумма · причина (`qualifyReason` бейджем: «бронь» / «чек ≥ 100 тыс.») · получатель (`SearchSelect`, placeholder = имя по правилу серым «Иванов · по кругу»). «В брак» — только в BulkBar и меню «⋯» строки.

## 5. Шаг 4 — «Оставшаяся первичка»
Подзаголовок: «Не дошли до брони и чек меньше 100 000 ₽. По умолчанию — в автобрак. Нужную сделку можно спасти.»
Группы-аккордеоны: «В автобрак · 13 · 410 000 ₽» (открыта), «Спасённые · 2», «Автобрака в воронке нет — передаём · 4» (с пояснением), «Не трогаем · N».
Строка: чекбокс · название · стадия · сумма · «Спасти» (`btnSecondary`, `min-h-9`) / у спасённой — `SearchSelect` получателя + «Вернуть в брак».
Панель: «В брак 13 · 410 000 ₽», «Спасаем 2»; «Кому уйдут спасённые» — контрол правила первички с подписью «Общее с шагом 3». Блокер: есть передаваемые строки и нет получателей.

## 6. Шаг 5 — «Задачи без сделок»
Колонка `max-w-[960px]` + справа `lg:w-[360px]` карточка РОПа.
Подзаголовок: «Задачи и дела, не привязанные к его сделкам, уйдут РОПу. Проверьте, кто это.»
Карточка: «РОП» — `SearchSelect` (подпись «Определён автоматически: …» / warning «не определился» — блокер); чекбоксы «Написать РОПу со ссылками на задачи», «Задача Анне Кузнецовой — сменить пароль».
Слева блоки по видам (`task_other`, `activity_other`, `task_creator`, `task_participant`): заголовок + счётчик + `Segment` действия на вид («РОПу / Завершить / Не трогать»; участник — «Убрать / Заменить / Не трогать»). Строки: название, срок (просрочен — `text-[var(--color-negative)]`), роль, «⋯» для исключения.
Внизу плашка `bg-[var(--color-bg-hover)] rounded-lg p-3`: «Задачи по сделкам — 48. Уйдут за сделкой: 41 новому ответственному, 7 закроются с автобраком.» + «Показать список» (`Modal`, только чтение).

## 7. Шаг 6 — «Итог и запуск»
`max-w-[1200px]`, `grid lg:grid-cols-2 gap-4`:
- Блокеры сверху (если есть): ErrorBox-список со ссылками «Шаг 1: 6 заказчиков без получателя → Перейти».
- «Кому сколько» — `<table>` в `<div className="scroll-x">`: Получатель · Повторка (сделок / заказчиков / LTV) · Первичка (сделок / сумма) · Задач следом; итог `bg-[var(--color-totals-bg)]`.
- «Не передаём»: закрываем повторку N (причина), автобрак N · сумма, остаётся на уволенном N.
- «РОПу и сообщения»: N задач → имя; сообщение да/нет; задача на пароль да/нет.
- Комментарий для истории.
- Блок запуска на всю ширину `card border-[var(--color-warning)]/40 p-4` (содержимое `ConfirmStartModal`, без модалки): WarnBox «Будет изменено N записей в Битриксе. Откатить нельзя.» → чекбокс «Я проверил получателей» → `btnPrimary` «Запустить · N записей» (disabled без галочки / при блокерах / при ошибке сохранения).

## 8. Общие компоненты
**ItemRow**: клик — фокус, чекбокс — выделение, Shift+клик — диапазон. Клавиатура: `↑/↓` (`j/k`), `Space` выделить, `Enter` выбор получателя, `1–9` назначить N-му из панели, `B` брак/закрыть, `Backspace` к правилу, `Ctrl/Cmd+A` всё отфильтрованное, `Esc` снять. Подсказка под списком `hidden lg:block`. Фокус `ring-2 ring-inset ring-[var(--color-border-focus)]`, выделение `bg-[var(--color-accent-soft)]`.
**cleanTitle**: ведущая фраза из ≥2 слов КАПСОМ («ПОСМОТРИ ЗАДАЧУ») → серый бейдж `text-[10px] uppercase rounded px-1.5 bg-[var(--color-bg-hover)]` после названия; `Сделка (B2B)` / `Сделка #123` → «Без названия · #123» muted; сумма 0/null → «—»; LTV 0 → «—».
**BulkBar** (при выделении заменяет нижнюю панель): «Выбрано 7 · LTV 3,2 млн» · `SearchSelect` «Передать…» · «В брак/Закрыть» · «К правилу» · «✕».
**RecipientTile**: `Avatar` 28 + имя `truncate` + горячая цифра `kbd`; справа «12 сделок · 9 зак.»; ниже LTV и полоска доли `h-1 rounded-full bg-[var(--color-accent)]`; отклонение от среднего LTV >25% — warning «перекос». Кликабельна при выделении.

## 9. Пустые / загрузка / ошибки
- Шаг без строк: `card py-12 text-center` «Повторных сделок нет — шаг можно пропустить» + «Пропустить →»; вкладка «нет».
- Аккаунт пуст: текущий текст + шаги 5–6 доступны (пароль).
- Справочники грузятся: `Skeleton` списка, селекты disabled «Загружаю сотрудников…»; ошибка — `ErrorBox` + «Повторить».
- Сохранение упало: красный статус в нижней панели + «Повторить», запуск заблокирован; 409 — перечитать прогон.
- Поиск пуст: «Ничего не нашлось · Сбросить».

## 10. Мобильная версия (375px)
- Степпер компактный (§1); сетка в одну колонку.
- Панель «Кому сколько» → липкая плашка над нижней панелью «Распределено 14 из 20 · 5 человек ▴», по тапу `Modal` (bottom-sheet) с плитками и правилом.
- Строка — карточка `p-3`: чекбокс `tap-target` + название; 2-я строка «LTV 1,2 млн · 14 отгр. · 2 сделки»; 3-я — `SearchSelect` во всю ширину `text-base`.
- Нижняя панель: «Назад» (иконка, `w-11`) + «Далее» `flex-1`; статус сохранения над кнопками `text-xs`. BulkBar — две строки.
- Шаг 6: карточки столбцом, таблица в `scroll-x`.
- `useAppMode().isMobileLayout` — только для «панель или sheet»; остальное — CSS-брейкпоинты. Клавиатурная подсказка скрыта.

## 13. Главные решения
1. Простыня → 6 шагов со свободным переходом; блокируется только запуск, блокеры — ссылками на шаги.
2. Ширина до 1680px, двухколоночно: список слева, липкая панель «Кому сколько» 360–420px справа.
3. Получатель прямо в строке (`SearchSelect` «Кому?»); «по правилу» — серый placeholder, не отдельный селект с подписью.
4. Панель получателей — живой подсчёт и палитра назначения (клик по плитке / 1–9 назначает выделенным).
5. Шум в названиях чистит один хелпер: капс-префикс → бейдж, «Сделка (B2B)» → «Без названия · #id», «0 ₽» → «—».
6. Топ-клиент без ручного получателя явно показывает, куда уйдёт; при правиле «Закрыть» это блокер.
7. На телефоне степпер — «Шаг 2 из 6 ▾» с полоской прогресса, панель — bottom-sheet.
8. Подтверждение — инлайн на шаге 6 (сводка + «Откатить нельзя» + галочка), без модалки.
