# Канбан больших чеков — спецификация (18.11.2026)

**Решения владельца 18.11:** общая сетка колонок для всех проектов (НЕ стадии каждого проекта) — сводим
по названию стадии (`features/big-deals-kanban/engine/config.ts`); вкладки «Доска» и «Сегодня» как в повторке;
видимость — общее правило Монолитики: менеджер — свои задачи, РОП/директор — агрегированно по иерархии;
при переносе в «Не продано» задачу завершаем.

Источники: постановка владельца 18.11; встреча 11.11 (Сергей Осипов — РОП «Больших сделок ОС»,
Леонид Коваленко, Миша), запись `temp/meeting_record_big_deals.webm`; живые данные Битрикса (REST, 18.11).

## Суть

Раздел `/big-deals-kanban` «по аналогии с повторкой», но **карточка = задача Битрикса** из проектов
больших сделок, не заказчик и не сделка. Пула слева нет: «это всё задачи, тут нет сделок» (Осипов).
Задачу создаёт Битрикс сам (робот: товары в сделке ≥ 150 тыс. ₽, выгрузка утром ~8:30) — не наша забота.
Новая задача стоит на РОПе (постановщик = ответственный = РОП), РОП изучает сделку, переназначает на
менеджера с указаниями и двигает по канбану.

Цель задач (Осипов): «дёргать менеджера, чтобы шёл по воронке» + вовремя дать подсказку, которую
менеджер не допёр (транзит на 300 упаковок, 3 шаланды вместо 4 манипуляторов, 90 упаковок в газель
вместо 97 в 5-тонник), и не проебать сделку.

## Карточка (максимум без перехода в Битрикс)

Сейчас карточка Битрикса: «товар | объём | адрес/фамилия», срок, статус, таймер — «низкоинформативна».
У нас на карточке:
- товарная группа и **сумма** сделки, менеджер, **стадия сделки**, дата создания задачи;
- **сколько дней задача в текущей колонке** (подсветка застрявших: «жизнь сделки — неделя», бронь
  две недели — ненормально); порог — настройка;
- статус задачи: не просмотрена / в работе / **ждёт контроля** / завершена;
- звонки после постановки (число, длительность, недозвоны) — «сделал три звонка или одно касание»;
- значок «товары менялись после постановки» (сверка позиций сделки с описанием задачи);
- связанные задачи по той же сделке — запрос логисту/снабженцу, «есть дешевле» — со статусом и
  отметкой «пришёл ответ» (сейчас Осипов каждый день проваливается в каждую сделку ради этого).

Открытая карточка (drawer): описание задачи (клиент, товары, цели, «есть ли цена дешевле», дата
поставки, 5 вопросов), товары сделки, **чат задачи прямо здесь** с шаблонами вопросов РОПа (~10 шт.,
задаёт админ), вложения, связанные задачи, ИИ-проверка ответов на 5 вопросов по звонкам после
постановки («ответил на 3 из 5, по 4 и 5 — нет»), карточка клиента с ИИ-анализом (ClientCardDrawer).

## Действия

- Переместить по стадиям (drag на десктопе, меню «Перенести в…» на таче).
- Сменить ответственного задачи (РОП → менеджер) с комментарием-ТЗ; РОП остаётся наблюдателем.
- Написать в чат задачи (шаблоны), приложить файл.
- Приёмка «ждёт контроля»: принять / вернуть на доработку со сроком (как AcceptTaskModal повторки).
- Разбор «Не продано (проверка)»: подтвердить → «Не продано (проверено)»; «пусть ещё раз позвонит» —
  вернуть менеджеру задачу на звонок, НЕ возвращая сделку в активную стадию.

## Сортировка и вид

Приоритет РОПа в сезон (Осипов): сначала «ждёт контроля» (менеджер ответил), затем подтверждённая
бронь → бронь → дальше по товарной группе (газобетон, вата, кровля…). Фильтры: товарная группа,
менеджер, сумма от/до, «застряли». Доска и «Сегодня» — по возможности в одном экране; отдельное
окно «Ждут приёмки» поперёк стадий.

## Итерация 2 (после первой выкатки)

- Автопереходы: стадия задачи следует за стадией сделки (роботы Битрикса делают это «не всегда»);
  «Назначил менеджера» без ответа сутки → «Проверить»; «Проверить важное» — личные правила РОПа
  (сумма ≥ 500 тыс./1 млн, бренд «Скандик» и т.п., механика своих колонок/автобрака повторки).
- Задача уходит в «Не продано» → снимать её с менеджера (закрывать), чтобы не висела «ждёт контроля»
  (на встрече: «джуниор, подумай» — нужно решение, как это сочетать с проверкой РОПа).
- Уведомление РОПу, когда по связанной задаче логиста/снабженца пришёл ответ.
- Аналитика: по менеджерам — сколько больших задач, продано/проебано, конверсия; подсветка тех, у
  кого конверсия ниже порога, → для правки распределения (вдохновлено: «у него конверсия 0, а
  большие сделки висят постоянно»).
- ИИ запрещает/предупреждает завершение задачи, если не на все вопросы есть ответ.

### Черновики и удобство постановки (собрание 26.11, ТЗ `tz/2026-11-26_big-deals-kanban.md`)

- **Черновик не пропадает.** Формы действий в шторке («Назначить», «Вернуть», «Принять», «Срок», «Возобновить»: открытая
  форма, менеджер, ТЗ/комментарий, срок) и «В Задачник» (текст, шаблон, постановщик, срок) хранятся в `localStorage`
  (`lib/hooks/useStoredDraft.ts`, ключи `draft:big-deals:<taskId>` и `draft:tasker-deal:<dealId>`, живут 3 дня).
  Переживают закрытие шторки (клик мимо, Esc, «Закрыть»), переход на связанную задачу и перезагрузку вкладки; если
  вкладка перезагрузилась при открытой форме, форма открывается снова. Чистятся успешной отправкой или «Сбросить
  черновик» в окне формы. На кнопке с черновиком — оранжевая точка. Клик мимо шторки закрывает её как раньше —
  черновик уже сохранён, поэтому без вопроса.
- Причина пропаж 26.11: `ServiceWorkerRegister` перезагружает ВСЕ открытые вкладки приложения, когда новый service
  worker берёт управление (`skipWaiting` + `clients.claim` → `controllerchange` → `reload`). Это происходит после
  каждой выкатки, как только приложение открывают в другой вкладке/окне. Плюс клик мимо шторки и переход на вкладку
  связанной задачи размонтировали форму. Теперь левая часть и чат задачи БЧ при открытой связанной задаче скрываются,
  а не размонтируются.
- «В Задачник»: срок — `DeadlineField` (день + время по Москве), по умолчанию «Сегодня», через час. Касается и
  «Задачи по сделке» в дриллдауне отчёта и канбане повторных — форма общая.
- Звонки во вкладке «Звонки и ИИ» свёрнуты в строку, разворачиваются по клику; «Развернуть все / Свернуть все».
- Выбранный менеджер в фильтре — сплошная акцентная заливка и «×» сброса рядом.
- Кнопки действий — акцентная рамка с заливкой (первичная — сплошная); «Закрыть» шторки — кнопка с текстом в шапке,
  на телефоне ещё круглая «×» слева внизу (зона большого пальца).

## Вне рамок (в BACKLOG)

- База знаний «хитростей» логистики с подсказками менеджерам.
- ИИ-подсказки переориентации (например, «70 % запросов на Скандик ушли в Изолайф»).
- Отдельный канбан допродаж (связки газобетон+клей, кровля+гидро…) — у Будковского, не смешивать.

## Технически

- Данные: `sa.bitrix_task_current` (group_id, stage_id, status, deal_id есть; копия из Roan раз в 5 мин)
  + прямой REST-доливок изменённых задач групп (обобщить `syncChangedProjectTasks` из
  `features/repeat-kanban/engine/taskReview.ts`, сейчас прибит к группе 118) + запись после своих действий.
- Время в стадии: Битрикс не отдаёт дату смены стадии — свой журнал переходов (первое появление
  задачи в стадии по синку) в system-БД.
- Запись: `task.stages.movetask`, `tasks.task.update` (RESPONSIBLE_ID, AUDITORS),
  `task.commentitem.add` от имени нажавшего (`callAsUser`), approve/disapprove — модули повторки.
- Переиспользуем как есть: TaskCheck/taskCheck (ИИ по taskId), taskNotes, Attachments, ParticipantsPicker,
  ClientCardDrawer (clientRef из сделки), формат гида (`guide/types.ts`).
- Права: новое право раздела; зона — участник проекта/РОП отдела; менеджер видит свои задачи.
