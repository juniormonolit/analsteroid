# «Ответы на запросы»: Монолитика ↔ Панель снабжения — сверка методик

Разбор 14.10.2026. Источник панели — архив кода с сервера `supply-panel.ds.mlt-it.com`
(доступ только на чтение: `ssh monolitika-ro@5.42.106.70 help|code|tables|sql`, выдан
решением Дмитрия Сивакова 08.10.2026), коммит панели `5504deae`. Наш отчёт —
`lib/realizations/responseMetrics.ts` + `features/reports/engine/requestResponse.ts`.

Правила обращения с данными панели: `tasks.title` содержит адреса/телефоны заказчиков —
не писать в логи, WORKLOG, бота «Аналитик»; цены и суммы — только внутри Монолитики;
SSH-ключ не встраивать в общедоступные места.

## Главное

1. **Разные объекты отчёта.** Панель — про **снабженцев** (строка = исполнитель,
   ответивший на запрос; срезы регион → департамент → категория-проект → снабженец).
   Наш отчёт — про **менеджеров-постановщиков** (`created_by`). Это два разных вопроса:
   «как быстро снабжение отвечает» vs «сколько запросов ставит менеджер и чем они кончаются».
2. **Разная вселенная запросов.** Панель: задачи в 29 **группах (проектах)** снабжения,
   с 01.01.2026, минус тестовые/удалённые/denied. Мы: задачи в **потоках** (`sa.bitrix_flows`)
   минус «Поддержка», «Акты сверок», «Коррекция заявок». Цифры заведомо не совпадут.
3. **Разное «ответ».** Панель: переход статуса OPEN(1,2,3,6) → DONE(4,5) по **истории**
   задачи; ответ засчитывается исполнителю в этот момент; возобновления дают циклы 2+.
   Мы: первый элемент `results[]` (любой автор), надёжно только с 07.09.2026, циклов нет.
4. **Разное время.** Панель: **рабочие часы** (пн–пт 09–18 МСК, праздники 2026), **средние**
   (у первого ответа ещё медиана). Мы: календарные часы, медианы, SQL без явного МСК.
5. **Разная атрибуция по периоду.** Панель: каждое событие — по своей дате (новые — по
   созданию, ответы — по ответу, продажи — по `sold_at`). Мы: всё по `created_at` задачи,
   статусы и сделки «на сегодня».
6. **Истории задач у нас в базе нет.** Панель тянет её REST-ом `tasks.task.history.list`
   (530 тыс. строк). Задачи и сделки — из того же Диспетчера (`sa.bitrix_task_current`,
   `sa.deals`), что и у нас.

## Правила панели, которые придётся повторить

- Тестовые задачи: `is_test(title)` — регэкспы `calc.py:232`; помечаются и выпадают из событий.
- Регион запроса = регион снабженца (большинство ответов за всю историю; исключения —
  `regions.json` с датами); нет снабженца — регион проекта. Департамент аналогично (ОС/НЦ).
- «Кто снабженец»: «Отдел снабжения» в оргструктуре **или** ≥ 100 ответов **или**
  `suppliers.json`; прочие сводятся в строку «Не снабженцы», из итогов не выпадают.
- Передача аккаунтов Bitrix24 (`accounts.json`, 10 аккаунтов): ответ — сотруднику на дату
  ответа, новые и продажи — на дату первого ответа.
- Итог сделки: побеждает более позднее из `sold_at`/`lost_at`; сделка целиком у каждого
  исполнителя, в итоге региона — один раз.
- Рабочие дни периода — знаменатель «в рабочий день»; праздники зашиты только на 2026.

## Чего у нас нет совсем (вкладки панели)

- **«Товары»** — позиции из таблицы в описании запроса (`goods`, с 21.07.2026), привязанные к
  каталогу Bitrix24 (~9 % «вне каталога»), услуги исключены: запросов, доля, сделок, продано, объём.
- **«Доля запросов»** — по всем сделкам с товарами с 01.01.2026: доминирующий узел каталога
  сделки и доля сделок, по которым был запрос снабжению («По наибольшему» / «По наличию»).

## Варианты переноса (решение владельца)

- **A. Зеркало + порт расчёта на TS (рекомендация).** Джоба раз в 15–30 мин тянет таблицы
  раздела по SSH (≈20 с, ~120 МБ) в отдельную схему нашей БД; `calc.py` (~320 строк) +
  `metrics.aggregate` переписываются на TS как движок отчёта (`SalesReportPage`), строки —
  снабженцы, срезы регион/департамент/категория; сверка с `report.py`. Ключ SSH — на
  прод-сервер (согласовать с Дмитрием).
- **B. Зеркало + их Python как есть** — быстрее, но чужой стек и мимо движка метрик.
- **C. Своя выгрузка истории из REST Bitrix24** — без зависимости от сервера панели, но
  повторять `pull.py` и вести справочники (`accounts/regions/suppliers`) самим.

Открытые вопросы владельцу: (1) наш менеджерский отчёт оставляем рядом или заменяем
снабженческим; (2) вселенная — проекты панели или наши потоки; (3) можно ли ключ на прод;
(4) нужны ли вкладки «Товары» и «Доля запросов» в первой очереди.
