# ТЗ: Задачник — постановка задач на РОПа и тренера (собрание 26.11.2026)

Источник: запись собрания 26.11 (Телемост, ~37 мин, расшифровка whisper). Где запись неразборчива — помечено
«уточнить». Код сверен 27.11: `features/tasker/engine/create.ts`, `features/tasker/ui/create/CreateTaskDrawer.tsx`,
`features/tasker/trainings/engine/{autoTheory,queue,calendar}.ts`, `TASKER_SPEC.md`.

## Главный принцип (решено на собрании)

**На менеджера задачи не ставятся никогда.** Работа с менеджером — это задача либо на **РОПа** («Практика»: РОП
садится с менеджером и разбирает), либо на **тренера** («Теория»). Менеджеру приходит только **уведомление**:
«с вами работа такого-то числа с 15:00 до 15:30 по „CR Сделка → Бронь“, ведёт РОП Новиков».
Сейчас задачи действительно не ставятся на менеджера (create.ts:206). Но РОПа нельзя выбрать исполнителем, а менеджер не получает ничего.

## 1. Исполнитель «Практики» — РОП, а не постановщик

**Как сейчас:** у «Практики» исполнитель = постановщик (create.ts:206). Директор хотел: постановщик — он сам,
исполнитель — РОП менеджера (Новиков). Выбрать РОПа можно было только постановщиком, и директор из задачи пропадал.

**Сделать:**
- В форме «Практики» отдельное поле **«Исполнитель»**. По умолчанию — РОП выбранного менеджера. Можно выбрать другого РОПа
  отдела, директора или себя. Список — по тем же правам, что у постановщиков (`creators.ts`).
- Постановщик остаётся тем, кто ставит (или выбранным «от имени», как сейчас).
- В Битриксе: `RESPONSIBLE_ID` = исполнитель, `CREATED_BY` = постановщик. Наблюдатели — как сейчас, без дублей.
- «Теория» без изменений: исполнитель — тренер.

## 2. Уведомление менеджеру (бот «Аналитик»)

**Как сейчас:** менеджер узнаёт только из приглашения в календаре Битрикса. Ни бот, ни колокольчик не срабатывают.

**Сделать:**
- При создании задачи с менеджером («Практика» со временем, «Теория» с записью на занятие) — личное сообщение бота
  менеджеру: что, когда (дата, время с–по), с кем (РОП/тренер), по какой метрике, где (если есть место или ссылка).
- При переносе или отмене — отдельное сообщение.
- Напоминание перед началом: по умолчанию за 30 минут. Варианты за день, за час и за 15 минут — настройкой в «Настройках»
  Задачника. На собрании сказали: колокольчик менеджеры пропускают, нужно именно сообщение.
- Отдельный канал в фичефлагах (по образцу `tasker_tests`), чтобы глушить целиком.
- Текст — через BB-коды Битрикса (LIST/QUOTE/TABLE не работают).

## 3. Пересечения по времени — запрет, а не предупреждение

**Как сейчас:** для «Практики» `AvailabilityWarning` только предупреждает, сервер сохраняет. На собрании поставили
двух менеджеров (Молочникова и Микитину) на одного РОПа на вторник 15:00 — так быть не должно.

**Сделать:**
- Сервер **отказывает**, если у исполнителя на это время уже есть задача Задачника, сессия или занятие (с учётом длительности).
  Событие календаря Битрикса извне — предупреждение, как сейчас: там бывает мусор.
- В форме при выборе дня — **лента занятости исполнителя** на этот день и ближайшие 3–5 рабочих дней: его задачи и сессии
  с временем, свободные окна кликабельны и подставляют время.
- То же для менеджера: у менеджера не может быть двух работ в одно время (РОП + тренер).

## 4. Несколько задач по одной метрике (вторник + четверг)

**Как сейчас:** правило `duplicate_metric` (create.ts:106-114, 178-180) запрещает вторую открытую «Практику» по той же
метрике тому же менеджеру. Директор хотел поставить работу по броням на вторник и на четверг — получил «вторую не ставим».

**Сделать:**
- Разрешить несколько открытых задач одного вида по одной метрике, если у них **разные даты**. Одна и та же дата — по-прежнему дубль.
- В форме — выбор **нескольких дат/слотов** за одну постановку: одна строка «вт 15:00, чт 15:00». Создаётся по задаче на каждую дату,
  каждая проходит проверку пересечений из п.3.
- Лимит 3 открытых задачи на менеджера: считать по группам «метрика», а не по штукам (уточнить у владельца).

## 5. Время у «Практики» обязательно

**Как сейчас:** пустое время уходит как 10:00 МСК (create.ts:271). На собрании задача встала «на понедельник без времени».
Без времени не работает ни проверка пересечений, ни уведомление «с 15:00 до 15:30».
**Сделать:** время и длительность у «Практики» обязательны. Явный режим «без времени, до даты» — отдельной галочкой
(уточнить, нужен ли он вообще).

## 6. Подсказка исполнителю — что именно делать

Задача, созданная от метрики, должна содержать **готовый план разбора для РОПа**, а не «проверить последние сделки».
Пример с собрания: «разобрать с менеджером последние N первичных сделок, где клиент ушёл; посмотреть, была ли отработка
и сметы; открыть отчёт с такими-то метриками». На собрании похвалили подсказки, которые уже есть в «Теории»: сделать так же для «Практики».
- Шаблон плана по каждой метрике каталога (редактируемый в «Настройках»), подставляется в описание задачи.
- Ссылки: на отчёт по менеджеру с нужными метриками и на список сделок за период.

## 7. Обучение (тренер): фиксированные слоты, запись РОПами, тема у тренера

Тренер описал, как ему удобно:
- Слоты фиксированы по отделам: Москва — вт и чт 16:15, Санкт-Петербург — каждый будний день в фиксированное время.
  Сетка `tasker_training_slots` это уже умеет.
- РОП **сегодня записывает людей на завтра** в слот. Тренер утром открывает Задачник и видит: «на сегодня записаны
  такие-то, повод — такие-то метрики».
- **Тему выбирает тренер**, а не метрика: метрика — повод, а что провести, решает он.
- Людям автоматически уходит напоминание (п.2).

**Сделать:**
- «Теория» без времени — **автоматически в ближайший подходящий слот отдела менеджера** (не раньше следующего дня, тренер свободен,
  в группе есть место). Не ждать минимума в 3 человека в очереди. Очередь остаётся только для тех, кому слот не нашёлся.
- У занятия поле **«Тема»** редактирует тренер (по умолчанию — из метрики). Смена темы уведомляет участников.
- Кнопка тренера **«Утвердить состав и тему»**: рассылает участникам сообщение с темой и временем. Альтернатива — автоматически
  накануне вечером (уточнить у тренера).
- Тот же человек на ту же тему повторно — без ручного перевбивания: «повторить занятие» на карточке.

## 8. Решено НЕ делать

Автоматическую постановку на обучение по метрике ниже средней по больнице **не делать**. Причины разбирают на собраниях,
ставят руками.

## Неразборчиво — уточнить у владельца

- «Вынести в важное куда-то наверх» в Задачнике — что именно закрепить сверху.

## Приёмка

- Директор ставит «Практику» на менеджера, исполнитель — РОП менеджера, директор — постановщик. В Битриксе так же.
- Менеджеру пришло сообщение бота с датой, временем с–по, исполнителем и метрикой; за 30 минут — напоминание.
- Вторая «Практика» тому же РОПу на то же время — отказ сервера с понятным текстом; в форме видно, что время занято.
- «Практика» по одной метрике на вт и чт создаётся одной постановкой, две задачи.
- «Теория» без времени сама попадает в ближайший слот отдела; тренер утром видит состав, меняет тему, участники получают сообщение.
- Работает на 375/768px и во всех четырёх режимах (`useAppMode`). `npm run typecheck`, `npm run test:reports` (если трогали), `lint:responsive`.
- `TASKER_SPEC.md` и WORKLOG обновлены.
