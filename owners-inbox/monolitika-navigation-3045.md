# Задача 3045. Перестройка навигации: ЛК на /profile

Дмитрий (архитектор), 04.08.2026. Код прочитан по ветке `dev-asteroid` (`/home/user/apps/analsteroid-wt-2654`). Код не менялся.

**Решение одной фразой:** `/profile` становится личным кабинетом (всё, что человек видит про себя), настройки самого себя — вкладки внутри ЛК, настройки системы остаются в `/settings/*`, и каждый закрытый раздел при прямом заходе честно отвечает «недостаточно прав» с сервера.

## 1. Карта адресов

| Адрес | Что | Кому |
|---|---|---|
| `/profile` | ЛК: карточка (то, что сейчас `/manager/me`, `app/(app)/manager/me/page.tsx`) | всем залогиненным, без прав |
| `/profile/team` | «Мой отдел» | всем; состав данных решает сервер |
| `/profile/settings?tab=personal\|notifications` + `?modal=password` | личные настройки: персонализация, уведомления, смена пароля | всем |
| `/settings/*` | настройки системы (как сейчас) | право `section.settings` |
| `/settings/trash` | общая корзина отчётов | `section.settings`; чужие отчёты — `action.shared_reports.manage` |
| `/manager/me` | редирект на `/profile` | — |
| `/manager/[id]` | чужая карточка/отдел — остаётся, на неё ведут отчёты и дайджест | `lib/org/managerAccess.ts` |
| `/bx/manager` | ЛК внутри Битрикса (embed-layout без шелла) | остаётся |

**Отступление от формулировки владельца, осознанное:** личные настройки и «Мой отдел» я кладу в ЛК, а не в `/settings`. Причина в его же требовании — «рядовой юзер не должен видеть ничего кроме ЛК»: `/settings` гейтится правом `section.settings`, и, положив туда смену пароля и уведомления, мы отберём их у всех рядовых. Вариант «личное — в /settings, но без гейта» рассматривал: дешевле на день, но тогда в одном разделе живут вещи с разными правилами доступа, и следующий разработчик поставит гейт на весь раздел и всё сломает. Выбран разнос по смыслу: «настройки себя» — в ЛК, «настройки системы» — в /settings.

**Адресуемость.** Вкладки ЛК — отдельные маршруты (`/profile`, `/profile/team`, `/profile/settings`), внутренние состояния — через `lib/hooks/useUrlState.ts` по правилу `ai_docs/fresh_docs/DESIGN_GUIDELINES.md:179+`: период `?from&to`, отдел `?dept=`, вкладка настроек `?tab=`, модалка пароля `?modal=password`, дефолты в URL не пишутся. Сегодня так нельзя: вкладки профиля — локальный `useState` (`features/profile/ui/ProfilePage.tsx:81,86,190`), ссылку на вкладку кинуть невозможно.

**Старые адреса.** Редиректы и совместимость не делаем (решение владельца). Смысл меняют два адреса: `/profile` (были настройки профиля — станет ЛК) и `/manager/me` (станет редиректом). Внешняя ссылка в приложение в шаблонах бота ровно одна — `lib/jobs/managerDigest.ts:551-553`, `https://monolitika.mlt-it.com/manager/{bitrixId}?tab=customers&customer=...`; `/manager/[id]` сохраняется, шаблон не ломается, но одну строку поправить надо: если менеджер открывает сам себя — вести на `/profile?tab=customers&customer=...`, иначе получим второй вход в собственный ЛК. Других исходящих ссылок нет (инвайты — `/invite/{token}`, виджет — `/widget-constructor`).

## 2. Права проверяются на сервере

Три рубежа, скрытие пунктов меню защитой не считается:

1. `proxy.ts:24-34` — только факт сессии (cookie `as_session`), без неё → `/login`. Не трогаем.
2. Серверный `layout.tsx`/`page.tsx` каждого закрытого раздела: `getSession()` + `hasPerm()` (`lib/auth/perms.ts:68-72`). **Изменение:** везде вместо `redirect(firstAllowedPath(session))` рендерить `components/ui/AccessDenied.tsx` — «Недостаточно прав» на месте запрошенного адреса, внутри обычного шелла, с кнопкой «В личный кабинет». Сейчас честный экран уже в 14 layout'ах, а редиректом молча уводят 8: `metrics/layout.tsx:9`, `settings/layout.tsx:18`, `sales`, `plans`, `charts`, `marketing`, `summary`, `decomposition` (все `layout.tsx:8`); плюс два самописных inline-текста — `offload/page.tsx:13-19`, `employees/page.tsx:13-19`.
3. API `app/api/**` — общий хелпер `permError(session, key)` / `superadminError()` (`lib/auth/perms.ts:76-86`). Из 167 роутов без него 9, и все с собственной аутентификацией (логин, инвайт, вебхуки Битрикса и телефонии, токены виджета) — дыр нет. Новые эндпоинты ЛК обязаны использовать тот же хелпер.

**Что получит неприглашённый.** «Неприглашённый» технически = аккаунт, автосозданный при входе из Битрикса (`lib/bitrix/appAuth.ts`, роль «Пользователь», пустой набор прав, пароль неизвестен даже владельцу). По прямой ссылке на отчёт он увидит экран «Недостаточно прав» на этом же адресе — не редирект на главную и не пустой экран. ЛК ему доступен всегда и правами не гейтится.

Режим «Обычная/Про» (`users.ui_mode`, `lib/auth/perms.ts:95-104`) — не право и не гейт: он прячет расширенные контролы внутри отчёта (`features/reports/ui/SalesReportPage.tsx:307-316`). Смешивать его с правами нельзя, оставляем как есть.

## 3. «Мой отдел» — половина есть, половина новая

Проверено по коду: экран существует, но только как вкладка внутри `/profile` (`features/profile/ui/ProfilePage.tsx:293-356`), и только для ролей РОП/Директор/Администратор (`ROSTER_ROLES`, там же строка 33). В навигации — ни в меню, ни в «Ещё» — ссылки нет вообще (`components/layout/AppShell.tsx`, `BottomTabBar.tsx`), поэтому «не находится». Рабочий код: `features/profile/ui/DeptRosterGrid.tsx`, API `app/api/manager-card/team/route.ts` (со своей проверкой `canViewDepartmentData`) и `app/api/me/dept-summary/route.ts`.

Состав `/profile/team` после доработки:
- Шапка: отдел пользователя, переключатель при нескольких отделах (`?dept=`), период (`?from&to`, дефолт — текущий месяц).
- **Руководителю** (перенос): таблица «Подконтрольные отделы» план/факт + сетка карточек подчинённых с мини-радаром, клик → `/manager/[id]`.
- **Менеджеру** (новое): сетка коллег своего отдела — имя, фото, место в рейтинге, % выполнения личного плана; без абсолютных сумм и чужих сделок, переход на чужую карточку заблокирован (`canViewManager` уже так и работает).
- Один эндпоинт `GET /api/team/roster`, который сам определяет охват и набор полей по сессии; фронт не выбирает режим. Роль-гейт строкой по имени роли заменить на охват из `lib/org/managerAccess.ts` — переименование роли не должно отбирать доступ.

## 4. Корзина отчётов

Сегодня вкладка «Отчёты» в профиле — единственный путь к восстановлению: `features/profile/ui/ReportsTrashCard.tsx:29` → `POST /api/saved-reports/[id]/restore`; список — `/api/saved-reports/trash` (сам чистит старше 30 дней). Переезд: тот же компонент под адрес `/settings/trash`, API не трогаем. Вкладку из профиля убирать **только** одновременно с выкаткой нового адреса, иначе восстановить удалённое будет нечем. Приоритет низкий, ~2 часа.

## 5. Стартовый адрес

Единая функция `landingFor(session)`: если у человека нет ни одного права `section.*` → `/profile`, иначе `/home`. Сейчас `firstAllowedPath()` (`lib/auth/perms.ts:111-113`) всегда даёт `/home`, а `app/login/page.tsx:23` жёстко пушит `/home` — обе точки правим.

| Режим (`lib/hooks/useAppMode.ts:17`) | Рядовой (прав нет) | РОП/директор/админ |
|---|---|---|
| `bitrix-iframe` | `/bx/manager` | `/bx/manager` (агрегат отдела уже есть) |
| `standalone` (PWA) | `/profile` (`app/manifest.ts:17,21`: `start_url` меняем, `id` — нет) | `/profile` |
| `mobile` | `/profile` | `/home` |
| `desktop` | `/profile` | `/home` |

`useAppMode` на маршрутизацию сейчас не влияет вообще (только высота iframe, SW, pull-to-refresh) — и не должен: режим определяет стартовый адрес ровно один раз, дальше работает обычная навигация. В Битриксе остаётся `/bx/*`: CSP `frame-ancestors` разрешает встраивание только для этих путей (`next.config.ts:18-45`), `/profile` в iframe портала даст белый экран.

4. Кнопка «Мой ЛК» (`features/profile/ui/ProfilePage.tsx:159-161`) и подсказка «Своя — в разделе Мой ЛК» (`app/(app)/manager/[id]/page.tsx:30`) — обе указывают на `/manager/me`.

6. Дайджест бота `lib/jobs/managerDigest.ts:551-553` — работать продолжит, но ссылку «на самого себя» надо перевести на `/profile` (одна строка в шаблоне).

9. Корзина: пока `/settings/trash` не выкачен, удаление вкладки «Отчёты» отрезает восстановление (см. п.4).
10. Дублирование ЛК: `/profile` и `app/(embed)/bx/manager/page.tsx` станут двумя реализациями одного экрана — тело ЛК вынести в общий компонент, оба маршрута рендерят его.
11. Гейт «Моего отдела» по имени роли (`ROSTER_ROLES`) — при переносе заменить на охват по оргструктуре.
12. Дев-стенд: новых миграций не требуется (права не добавляем), гард автодеплоя не сработает; при появлении нового permission-ключа миграцию применять руками.
