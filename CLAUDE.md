# Аналстероид — правила для Claude Code

BI-дашборд продаж (Next.js 16 App Router, React 19, Tailwind v4, TanStack Query, Radix UI).
Документация проекта — `ai_docs/fresh_docs/` (PROJECT_OVERVIEW, WORKLOG, SECRETS_AND_STORAGE).
Каждое изменение/решение фиксировать в `ai_docs/fresh_docs/WORKLOG.md`.

**Отложенное и недоделанное — `ai_docs/fresh_docs/BACKLOG.md`**, единственный
актуальный список. Новая отложенная задача → строка туда (не только в память
сессии: она локальна и другим агентам не видна). Сделана → удалить оттуда,
подробности в WORKLOG. Раздел «формат обсудить до постройки» — не начинать
самостоятельно, там ждут решения владельца.

## Git и деплой — ОБЯЗАТЕЛЬНО (над проектом работают несколько агентов параллельно)

Ветка разработки — `dev-asteroid`, над ней одновременно работают несколько агентов.
Локальное дерево устаревает за минуты, поэтому:

1. **Перед началом работы и перед КАЖДЫМ деплоем** — `git pull origin dev-asteroid`.
   Работать поверх актуального `HEAD`, а не поверх своего локального состояния.
2. **Перед выкаткой** убедиться, что деплоится коммит, в который `origin/dev-asteroid`
   уже влит: `git merge-base --is-ancestor origin/dev-asteroid HEAD`. Если нет —
   сначала `pull`/`merge`, только потом `deploy.sh`. Иначе выкатка откатит прод к
   состоянию без чужих коммитов (уже случалось: деплой уехал, пока ветка ушла вперёд).
   Проверка встроена в `deploy.sh` и падает сама; осознанно обойти —
   `ALLOW_STALE_DEPLOY=1 bash deploy.sh`.

Перед `git pull` и любой командой, способной затереть незакоммиченное
(`checkout`/`reset`/`clean`), сначала `git status`.

## Адаптивность — ОБЯЗАТЕЛЬНО для любого UI-кода

Приложением пользуются с телефонов и планшетов. Любой новый или изменённый экран обязан
работать на ширине **375px** (телефон) и **768px** (планшет), а не только на десктопе.
План массовой адаптации существующих страниц: `ai_docs/fresh_docs/MOBILE_OPTIMIZATION_PLAN.md`.

Правила (нарушение = баг, а не «улучшим потом»):

1. **Никаких фиксированных ширин без ограничителя.** `w-[800px]`, `style={{ width: 600 }}`
   и т.п. — только вместе с `max-w-full` / `max-w-[calc(100vw-16px)]` / `max-w-[94vw]`.
2. **Каждая `<table>` — внутри `<div className="scroll-x">`** (класс в `globals.css`:
   overflow-x + инерционный скролл iOS). Широкая таблица без обёртки ломает всю страницу.
3. **Модалки — только `components/ui/Modal`** (Radix: на десктопе окно, на телефоне
   bottom-sheet). Самописные `fixed inset-0` с фиксированной шириной — запрещены.
4. **Дропдауны/поповеры — только `components/ui/Popover`** (Radix сам прижимает панель
   к краям вьюпорта). Позиционирование через `getBoundingClientRect` + `position:fixed` —
   запрещено: на узких экранах панель уезжает за край.
5. **Hover-only элементы недоступны на таче.** Вместо `opacity-0 group-hover:opacity-100`
   использовать класс `hover-reveal` (виден на тач-устройствах, прячется до hover на десктопе).
6. **Мелкие иконки-кнопки** (`<Trash2 size={12}/>` и т.п.) — добавлять класс `tap-target`
   (расширяет зону нажатия до 44px без изменения вида). Полноразмерные кнопки/вкладки —
   не полагаться на паддинги «на глаз», держать `min-h-11` (=44px) явно.
7. **Высота экрана — `h-dvh`, не `h-screen`** (h-screen на мобильном Safari прячет контент
   под адресной строкой).
8. **Ветвление по устройству в JS** — хуки из `lib/hooks/useMediaQuery.ts`
   (`useIsMobile`, `useIsTablet`, `useIsTouch`), но сначала пробовать чистый CSS
   (`sm:` / `md:` / `lg:` префиксы Tailwind) — он не требует гидрации.
9. **Формы**: гриды `grid-cols-2/3` — с мобильным вариантом `grid-cols-1 sm:grid-cols-2`.
   Инпуты — `font-size` ≥ 16px на мобильном (иначе iOS зумит при фокусе) или `text-base sm:text-sm`.
10. **Перед завершением UI-задачи**: `npm run lint:responsive` — новых нарушений быть
    не должно (скрипт сравнивает с baseline и падает на новых). Плюс визуальная проверка
    в превью на ширине 375px.
11. **Режим запуска — только через `useAppMode()`.** Приложение открывают четырьмя
    способами: десктоп-браузер, мобильный браузер, установленное PWA (standalone,
    без адресной строки) и iframe внутри Битрикса. Любой новый UI, которому нужно
    вести себя по-разному в зависимости от режима (навигация, диалоги/модалки,
    поведение «назад», что показывать при отсутствии сессии и т.п.), ОБЯЗАН
    спрашивать `lib/hooks/useAppMode.ts`, а не изобретать свою проверку
    `window.self`/`matchMedia('display-mode')`/`navigator.standalone`/User-Agent.
    Контракт хука (четыре режима, `isMobileLayout`, ловушка SSR) — в
    `ai_docs/fresh_docs/DESIGN_GUIDELINES.md`, раздел «Режимы запуска (useAppMode)».
    Работать во всех четырёх режимах — обязательное условие приёмки, не «покрыли
    десктоп и мобильный, остальное потом».
12. **Горизонтальная лента вкладок/чипов (`overflow-x-auto`) — три вещи ОБЯЗАТЕЛЬНЫ,
    не только сам скролл** (живой инцидент задачи 2779: владелец на iPhone свайпнул
    полосу вкладок ЛК — уехала ВСЯ СТРАНИЦА, а не полоса):
    - на РОДИТЕЛЕ ленты (flex-item, который её оборачивает) — обязателен `min-w-0`.
      Без него flex-item держится за content-based ширину ребёнка (все вкладки целиком),
      `overflow-x-auto` внутри перестаёт быть реальной границей скролла, и лишний
      избыток утаскивает вбок предка — вплоть до `<body>`, если где-то по цепочке
      родителей стоит одноосевой `overflow-y-auto` (CSS-спека трактует его как auto
      по ОБЕИМ осям, раз хоть одна не `visible`) — отсюда правило 13 ниже;
    - индикатор «есть продолжение» — градиент-затухание у края (только когда правда
      есть что скроллить — `scrollLeft`/`scrollWidth`, не декоративная стрелка) +
      `.scrollbar-none` (класс в `globals.css`) вместо голого системного скроллбара;
    - активная вкладка — автоскролл в видимую область при монтировании (без анимации)
      и при смене (плавно): `element.scrollIntoView({ inline: 'nearest' })` по
      `data-tab-key`/`data-tab-id`. Заход по прямой ссылке на вкладку в конце списка
      обязан сразу показывать, что она активна, а не оставлять её за краем.
    Готовый эталон — `ManagerTabBar`/`ReportTabsBar` (`features/manager-card/ui/ManagerTabs.tsx`,
    `features/reports/ui/ReportTabsBar.tsx`). Альтернатива для небольшого числа вкладок —
    `flex-wrap` (перенос на новую строку) вместо скролла вообще снимает этот класс
    бага — см. `TabBar` в `features/badges/ui/RewardsSettingsPage.tsx`.
13. **Page-root контейнер (`h-full overflow-y-auto` — устоявшийся паттерн этого
    проекта) — держать `overflow-x-hidden` рядом ВСЕГДА**, даже если сейчас внутри
    вроде бы нечему течь вбок. Без него любая будущая ошибка по правилу 12 (или
    любая другая забытая ширина) тихо превращается в горизонтальный скролл всей
    страницы вместо локального бага одного виджета. `npm run lint:responsive` ловит
    отсутствие `overflow-x-hidden` рядом с `h-full overflow-y-auto` — новое правило
    `page-root-missing-overflow-x-hidden` (задача 2779).
